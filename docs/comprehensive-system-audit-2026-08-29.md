## Issues found and fixed

### 1. OAuth logging could include raw provider error detail

`backend/src/routes/auth.js` used `console.error` with a raw Discord response or
exception message. It now uses the central redacting logger and retains only:

- request ID;
- HTTP status;
- bounded Discord error category.

No token, provider response body, credential, stack, or arbitrary exception
message is logged by that path. Malformed public-origin configuration warnings
also use the central logger.

### 2. Discord command sweep had stale mocks

The manual all-command executor lacked current `client.config`, `allByPrefix`,
and `deletePrefix` behavior. That caused a false crash for `/warn` and a handled
rank-card warning even though production supplies those dependencies.

The test harness now uses validated Bot Config V2 and the current database
adapter contract.

Result:

```text
Targeted command checks: PASS
Commands executed:      100
Command crashes:          0
```

### 3. Dashboard smoke test could not distinguish secure degraded mode

The manual Dashboard smoke suite previously treated expected unauthenticated
`401` responses and an offline bot as failures, making it unusable in
credential-free CI/local environments.

It now supports:

```bash
ALLOW_DEGRADED=true node tests/manual/dashboard-smoke.js
```

Strict behavior remains the default. Degraded mode accepts only the expected
`401` protection and offline health state; SPA/assets/auth-status must still
work.

## External limits

The following cannot be truthfully marked live-tested without newly rotated
provider credentials and provider access:

1. Discord gateway login, OAuth callback, guild actions, and voice playback;
2. real Supabase PostgreSQL migrations/transactions/session persistence;
3. Supabase Storage avatar upload/delete;
4. Resend sender-domain delivery;
5. strict Render readiness and physical-device visual acceptance.

The code paths have unit/security/integration coverage, but old exposed
credentials must never be reused. Configure new values directly in Render and
follow `docs/deployment/deployment-live-runbook.md` for strict acceptance.
