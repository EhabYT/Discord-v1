### Confirmed build duplication

Root `npm ci` executes the root `postinstall` script:

```text
npm --prefix dashboard ci --ignore-scripts
npm run build:dashboard
```

The Render build command then runs `npm run build:dashboard` a second time.
Therefore every Render deployment currently compiles the same Dashboard twice.
The safe optimized command is `npm ci`, retaining the automatic postinstall
build and its missing-build protection.

## CI design requirements

The new workflow must:

1. run on pushes to `main`, pull requests, and manual dispatch;
2. use exactly Node 22.12.0;
3. install root and Dashboard dependencies from lockfiles with `npm ci`;
4. avoid postinstall/build duplication during CI installation;
5. execute the authoritative `npm run verify` gate;
6. grant only read access to repository contents;
7. cancel stale runs for the same branch/PR;
8. use a bounded timeout;
9. persist no checkout credentials;
10. pin third-party actions to immutable commit SHAs.

## Configuration validation requirement

A repository-local, credential-free validation script must fail when:

- Node pins diverge;
- the Render build/start/health/auth production contract changes unexpectedly;
- a Render secret receives a committed literal value;
- the CI workflow omits the authoritative release gate;
- actions are referenced by mutable tags rather than full commit SHAs;
- CI permissions, timeout, dependency installation, or triggers regress.

The script must become part of `npm run verify`, making local and CI policy the
same executable contract.
